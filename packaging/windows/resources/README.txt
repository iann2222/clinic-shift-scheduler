========================================
執行方式（共兩種）
========================================

方式一：完整 UI（一般使用者首選）
1. 雙擊 clinic-shift-scheduler.exe。
2. 建立或開啟 input 資料夾內的月份資料，完成輸入檢查並儲存。
3. 按右上角「設定」調整執行與候選設定。
4. 到「執行排班」頁執行目前月份，並在畫面查看進度、耗時與輸出路徑。
5. 到 output 資料夾取得 JSON、Excel 與 PDF。

方式二：quick-runner.exe（熟悉檔案設定者）
1. 直接編輯 config.json，以及 config 指定之 input 資料夾內的月份 JSON。
2. 雙擊 quick-runner.exe；程式會依設定完成輸入檢查、求解與正式輸出。
3. 在主控台查看進度與錯誤，完成後到 output 資料夾取得結果。
直接雙擊執行時，排班完成或發生錯誤後視窗會保留，閱讀訊息後按 Enter 才會關閉。從 PowerShell 或其他既有終端執行時不會額外等待。


========================================
這個程式是怎麼運作的？
========================================

簡單來說：你告訴程式「這個月要怎麼排」，它依照固定的規則幫你排出班表。

告訴的方式是這兩個輸入檔案：

1.【排班輸入】放在 input 資料夾，檔名類似於「排班輸入_2026-08.json」。
   其中記錄這個月的排班條件，例如：
   - 診所這個月每天哪幾個時段開診、各個時段需要幾位櫃檯／跟診
   - 有哪些員工、誰這個月要上幾節班、誰哪天請假或不能上班

2.【config.json】放在程式旁邊
   記錄「怎麼執行」的設定，例如：
   - 要用哪一份排班輸入
   - 結果輸出到哪裡、要不要覆蓋舊結果

所以兩種執行方式做的事完全一樣，差別只在「怎麼編輯這兩個輸入檔案」：
- 用方式一的 clinic-shift-scheduler.exe：它提供完整圖形介面協助「編輯、檢查並儲存」這兩個輸入檔案，之後執行排班，它會在背景呼叫排班程式來完成。
- 用方式二的 quick-runner.exe：它直接讀取你手動編輯好的這兩個輸入檔案，馬上開始排班。

也就是說，圖形介面和排班程式其實是可獨立的兩件事：
「圖形介面」只是幫你維護輸入檔案的編輯工具，排班表都是根據輸入檔案執行核心排班算法去得出的。無論是用哪一種方式編輯或執行，最後用的都是同一套排班邏輯。
所以只要控制好輸入的兩個檔案，哪種方式都能完成一樣的排班。

整個流程是：

    排班輸入 + config.json（兩個檔案）
              │
              ▼
        程式執行排班
   （先檢查輸入 → 依固定規則安排班表 → 檢查結果沒有違規）
              │
              ▼
    output 資料夾內的三份結果：
    - 排班結果_YYYY-MM.result-v1.json（完整資料，內容最詳細）
    - 排班結果_YYYY-MM.result-v1.xlsx（Excel 班表，適合編輯表格）
    - 排班結果_YYYY-MM.result-v1.pdf （單頁班表，方便直接查看）

正式結果完成後，程式可能還會額外找幾份「品質一樣好」的其他班表作為候選班表供參考。


========================================
注意事項
========================================
- 整個資料夾必須一起保留，請勿刪除或移動 _internal。
- clinic-shift-scheduler.exe 會以 quick-runner.exe 的獨立背景程序執行排班；介面本身不載入求解器，因此 quick-runner.exe 仍可單獨使用。
- input、output 與 config.json 可能含有個人資料，請妥善保管。
- 發布包內的月份資料是匿名範例，可直接用於首次測試。
- 若已有自己的 config、input 或 output，更新版本前請先備份；不要直接以新 ZIP 覆蓋既有資料夾。
- 正式檔案產生後才會開始候選處理；在編輯器可按「終止候選處理」，獨立主控台則按 Ctrl+C，均不影響已完成的正式結果。
- 第三方元件聲明、完整授權條款與 Qt LGPL 原始碼資訊集中在 licenses 資料夾。

發生錯誤時，可保留主控台訊息、使用的 config.json 與輸入資料供維護者檢查。
